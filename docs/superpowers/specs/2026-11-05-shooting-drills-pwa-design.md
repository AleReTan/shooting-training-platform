# Спека: Библиотека стрелковых упражнений (PWA)

**Дата:** 2026-11-05
**Статус:** согласовано с заказчиком (архитектурная фаза brainstorming)
**Рабочее название:** TrainingPlatform (финальное имя не выбрано)

## 1. Цель и аудитория

Легковесное офлайн-PWA — справочник стрелковых упражнений с тегами по навыкам.
Пользователи: сам автор + друзья и стрелковый клуб (русскоязычные). Без бэкенда,
без аккаунтов; обмен данными (в будущем) — файлом.

Приоритет оружия: **карабин — единственная дисциплина MVP**. Ружьё и
травматический пистолет — будущие расширения (схема данных готова к ним с первого
дня).

> **Поправка от 2026-11-05 (решение владельца):** дисциплины расширены до
> `carbine | shotgun | pistol-traumatic` — импорт с shootie.pro охватывает все
> типы оружия, каталог получил фильтр «Оружие». Валидатор принимает любое
> непустое подмножество дисциплин.

Языки: **русский первичный** (интерфейс и тексты), английский — fallback-поля
данных и англоязычные названия упражнений.

Упражнения — **только реальные, проверенные** (классика тренировочной литературы,
схемы USPSA / Steel Challenge и т.п.). Выдуманные упражнения не добавляются.
Копирайт: параметры упражнений (дистанции, пар-таймы, схемы мишеней, расход
патронов) — факты, используются свободно; тексты описаний — собственные;
у каждого упражнения обязательна атрибуция источника. Проект некоммерческий.

## 2. Ключевые решения

| Решение | Выбор |
|---|---|
| Форма | PWA (устанавливается на домашний экран) |
| Хостинг | GitHub Pages, деплой через GitHub Actions |
| Стек | Vite + Preact (SPA), TypeScript |
| Бэкенд | Отсутствует; все данные в браузере |
| Контент | JSON-файлы в репозитории («контент как код») |
| Единицы | Метры, секунды |
| Таймер | В MVP: стартовый сигнал + пар-тайм (Web Audio) |
| Схемы мишенной обстановки | Рендер из данных (SVG), для каждого упражнения |
| Визуал | Основное — авто-анимация схемы из данных (килобайты, офлайн); свои лёгкие видео/GIF в репо; внешние ссылки (YouTube и т.п.) только опционально — из РФ доступ нестабилен |

## 3. Архитектура

```
TrainingPlatform/
├── data/
│   ├── drills/*.json        # одно упражнение = один файл
│   ├── courses/*.json       # курсы/программы: упорядоченные наборы упражнений
│   ├── taxonomy.json        # дерево тегов навыков (RU/EN)
│   └── sources.json         # реестр источников: отображаемые данные об
│                            # origin, на которые ссылаются drills/courses
├── src/
│   ├── features/
│   │   ├── library/         # каталог, фильтры, карточка  ← MVP
│   │   ├── timer/           # таймер с бипом              ← MVP
│   │   ├── logbook/         # кабинет, история, статистика ← фаза 2
│   │   ├── calculators/     # хитфактор, конвертеры        ← фаза 2
│   │   └── groupAnalyzer/   # анализ групп на канвасе       ← фаза 3
│   ├── app/                 # оболочка, роутинг, i18n, PWA, layout-рендер SVG
│   └── ui/                  # общие UI-компоненты
└── tools/
    ├── validate-data/       # валидация схемы данных (запуск в CI) ← MVP
    └── scraper/             # импорт внешних архивов (USPSA и т.п.) ← фаза 2
```

- Роутинг: `preact-router` (или hash-роутер — решить при реализации; для
  GitHub Pages важна корректная работа SPA-фallback).
- Данные упражлений импортируются в сборку (bundle), поиск/фильтрация — на
  клиенте по загруженному массиву.
- Service Worker (Workbox): precache приложения и данных; кеш-версионирование по
  хэшу сборки; медиа — RuntimeCaching по требованию (см. §7).
- CI (GitHub Actions): валидация данных → сборка → деплой на Pages. Невалидный
  JSON блокирует деплой.

Изоляция модулей: каждый `features/*` не импортирует внутренности других
фич — только общие `ui/`, `app/` и слой данных. Это точка расширения: новые фичи
(logbook, calculators, groupAnalyzer) добавляются без правок в существующие.

## 4. Схема данных упражнения

Файл: `data/drills/<id>.json`. `schemaVersion: 1`.

```jsonc
{
  "schemaVersion": 1,
  "id": "carbine-1-to-5",                    // slug, уникальный, kebab-case
  "name": { "ru": "От 1 до 5", "en": "1-to-5" },
  "discipline": ["carbine"],                  // непустое подмножество:
                                              // "carbine" | "shotgun" | "pistol-traumatic"
                                              // (см. поправку в разделе «Приоритет оружия»)
  "source": {                                  // ОБЯЗАТЕЛЬНО: атрибуция
    "origin": "Kyle Lamb",                     // автор/происхождение упражнения
    "kind": "classic",                         // classic | uspsa-classifier | steel-challenge
                                              // | book | forum | adaptation
    "url": "https://…"                         // ссылка, если есть
  },
  "tags": ["first-shot", "accuracy", "transitions"],   // только из taxonomy.json:
                                              // теги навыков И теги условий (см. §6)
  "difficulty": 3,                             // 1–5
  "fireMode": ["live", "dry"],                 // "live" | "dry" | оба
  "rounds": 15,                                // расход патронов на один проход
  "distance": { "min": 25, "max": 25, "unit": "m" },
  "targets": [                                 // что на рубеже
    { "type": "ipsc-metric", "count": 1 }      // типы: справочник типов мишеней в taxonomy
  ],
  "parTimes": [                                // опционально, отсечки по уровням
    { "level": "novice", "time": 8.0 },
    { "level": "intermediate", "time": 6.0 },
    { "level": "master", "time": 4.0 }
  ],
  "scoring": { "type": "par-time" },           // par-time | hit-factor | points | none
  "goal":      { "ru": "…", "en": "…" },       // что развивает упражнение
  "steps":     { "ru": ["…"], "en": ["…"] },   // порядок выполнения, свои тексты
  "safety":    { "ru": "…" },                  // заметки по технике безопасности
  "equipment": ["карабин", "2 магазина"],      // необходимое снаряжение
  "layout": { /* см. §5, опционально */ },
  "media": {                                   // опционально, пусто допустимо
    "images": [ { "url": "…", "credit": "…" } ],
    "video":  [ { "provider": "youtube", "id": "…", "credit": "…" } ]
  },
  "variants": ["упрощение…", "усложнение…"],   // опционально
  "related": ["bill-drill"],                   // id похожих упражнений, опционально
  "needsReview": false                         // true для необработанного скрапа (фаза 2)
}
```

Валидация (запускается в CI на каждый push):
- уникальность `id`; `tags` ⊆ таксономии; `discipline` из справочника;
- заполнены `name.ru`, `steps.ru`, `goal.ru`, `source`;
- `related` ссылаются на существующие id;
- единицы — только `m`; время — секунды (число);
- для `scoring.type = hit-factor` поле очков обязательно.

### 4.1. Курсы (программы упражнений)

Отдельная сущность: тренировки вроде материалов **T-Rex Arms** — это не
разрозненные базовые упражнения, а упорядоченные программы, и в каталоге они
идут именно как курсы, а не как drills.

Файл: `data/courses/<id>.json`:

```jsonc
{
  "schemaVersion": 1,
  "id": "trex-carbine-fundamentals",
  "name": { "ru": "Карабин: база по T-Rex Arms", "en": "…" },
  "source": { "origin": "T-Rex Arms", "kind": "course", "url": "…" },
  "description": { "ru": "что это за программа и для кого" },
  "structure": [                             // фазы/недели, опционально
    { "label": { "ru": "Фаза 1: база" } }
  ],
  "items": [
    { "drillId": "carbine-1-to-5", "order": 1, "structureIndex": 0, "note": { "ru": "…" } },
    { "drillId": "bill-drill-carbine", "order": 2, "structureIndex": 0 }
  ],
  "media": { /* как у drill, опционально */ }
}
```

Валидация курсов: `drillId` существуют; `order` уникальны; курс непустой.
Упражнение может входить в несколько курсов. В карточке упражнения — обратная
ссылка «входит в курсы». Прогресс прохождения курса — фаза 2 (logbook).

## 5. Схема мишенной обстановки (layout → SVG)

Опциональный блок `layout` — координатное описание рубежа. Приложение рендерит
SVG-схему (стиль брифов USPSA: позиции стрелка, мишени с типами, укрытия,
дистанции, стрелки движения).

```jsonc
"layout": {
  "unit": "m",
  "width": 15, "depth": 25,                    // габариты рубежа для масштабирования
  "positions": [ { "id": "P1", "x": 2, "y": 1, "label": "старт" } ],
  "targets":   [ { "id": "T1", "x": 5, "y": 20, "type": "ipsc-metric" },
                 { "id": "T2", "x": 9, "y": 22, "type": "steel-circle" } ],
  "barriers":  [ { "x": 7, "y": 12, "kind": "barrel" } ],       // опционально
  "movement":  [ { "from": "P1", "to": "P2", "style": "advance" } ] // опционально
}
```

Свойства подхода: схема есть у каждого упражнения без ручной графики; единый
стиль; малый вес; полный офлайн; нет копирайт-рисков; правка схемы = правка
чисел. Рендер — чистая функция `layout → SVG` (легко тестируется).

## 6. Таксономия навыков

`data/taxonomy.json` — дерево тегов с RU/EN подписями. У каждого тега поле
`group` (фильтры в UI рисуются по группам). Начальный набор (карабинная +
тактическая ось, расширяемый правкой файла без правок кода):

**Группа «навыки»:**
- `first-shot` — первый выстрел
- `reload` — перезарядка (подвиды: `reload-tactical`, `reload-emergency`)
- `transitions` — перенос огня (мишень→мишень)
- `movement` — стрельба в движении (`movement-forward`, `movement-retreat`, `movement-lateral`)
- `precision-long` — точный дальний выстрел
- `recoil-control` — удержание / контроль отдачи
- `positions` — позиции (`standing`, `kneeling`, `prone`, `barricade`)
- `bilateral` — смена плеча / двусторонняя работа
- `cover` — работа с укрытием
- `speed` — скорость
- `accuracy` — точность

**Группа «условия» (тактический контекст — заказчик занимается тактической
стрельбой; упражнения с такими требованиями обязательны в базе):**
- `nvg` — выполнение под ПНВ (ночник)
- `armor` — обязателен бронежилет
- `helmet` — обязателен шлем
- `stress` — стрельба на пульсе: физнагрузка (спринт, бёрпи, отягощения)
  перед и/или между подходами для разгона пульса

Там же: справочник типов мишеней (`ipsc-metric`, `ipsc-classic`, `steel-circle`,
`steel-popper`, `a4-paper`, …) и уровни пар-таймов.

## 7. Визуал: анимации и медиа (с учётом блокировок РФ)

YouTube и многие внешние ресурсы из России доступны нестабильно, поэтому визуал
строится на своих ресурсах, внешние — только опциональные ссылки.

- **Приоритет 1 — авто-анимация схемы из данных (основной визуал).** Блок
  `layout` расширяется секцией `sequence` — порядок поражения мишеней,
  перемещения, перезарядки:

  ```jsonc
  "sequence": [                                  // опционально
    { "action": "engage", "target": "T1", "shots": 2 },
    { "action": "move",    "from": "P1", "to": "P2" },
    { "action": "reload" },
    { "action": "engage", "target": "T2", "shots": 5 }
  ]
  ```

  Приложение **проигрывает упражнение** поверх SVG-схемы: мишени подсвечиваются
  в порядке обстрела (с числом выстрелов), стрелок перемещается по позициям,
  пауза на перезарядку. Технологии: SVG/CSS-анимация (или Web Animations API).
  Свойства: килобайты веса, полный офлайн, генерируется из данных, есть у
  каждого упражнения с известным порядком, ноль копирайта, правка = правка JSON.
  Плюс кнопка «показать по шагам» (стейт-машина по тому же `sequence`).

- **Приоритет 2 — свои лёгкие медиафайлы в репозитории.** Короткие WebM/MP4
  (без звука, низкое разрешение) или GIF в `public/media/`; бюджет ~≤2 МБ на
  файл. Отдаются с нашего же хостинга (GitHub Pages) — не зависят от внешних
  сервисов. Кешируются по требованию («скачать визуал упражнения» /
  «скачать всё») в RuntimeCache; в базовый precache НЕ входят. База, тексты,
  SVG-схемы и анимации — офлайн всегда.

- **Приоритет 3 — внешние ссылки (YouTube и т.п.).** Только ссылками в блоке
  медиа/источника (открываются в браузере, не встрока). Встрока опциональна и
  с graceful-заглушкой, если не грузится.

Обработка ошибок: медиа недоступно — аккуратный placeholder, приложение
работает; сеть отсутствует при первом заходе — заглушка «повторить»;
Service Worker обновляет кеш в фоне по хэшу сборки.

## 8. Скоуп MVP

Входит:
1. Каталог: поиск по названию/тексту; фильтры — теги (навыки и условия —
   раздельные группы: в т.ч. «под ПНВ», «в броне», «в шлеме», «на пульсе»),
   сложность, fireMode, расход патронов, дистанция.
2. Карточка упражнения: описание, SVG-схема обстановки + **проигрывание
   упражнения** (авто-анимация по `sequence`: порядок мишеней, движение,
   перезарядки; см. §7), параметры, пар-таймы, источник, варианты, похожие,
   «входит в курсы».
3. **Курсы/программы:** страница курса с упорядоченным списком упражнений
   (начало с программ на основе материалов T-Rex Arms — параметры упражнений
   из их тренировок, свои тексты, атрибуция).
4. Таймер: стартовый сигнал (бип), пар-тайм из карточки упражнения, случайная
   задержка старта. Web Audio, работает офлайн, экран не гаснет
   (Wake Lock API, где доступен).
5. PWA-офлайн: precache приложения и данных; установка на домашний экран
   (manifest, иконки).
6. Контент: **100+ реальных карабинных упражнений + минимум 1–2 курса**,
   русские тексты, атрибуция (см. §9).
7. RU-интерфейс; EN-поля данных как fallback.

Не входит (осознанные non-goals MVP): кабинет/история тренировок, калькуляторы,
анализ групп, скрапер, собственные видеозаписи (только авто-анимации и,
опционально, лёгкие чужие/своие файлы по требованию), ружьё/травмат,
EN-интерфейс, серверная синхронизация.

## 9. Контентный пайплайн

1. **MVP:** библиотека пишется по известным публичным параметрам реальных
   упражнений — карабинная классика (Kyle Lamb 1-to-5, 5-50-5, позиционные,
   перезарядочные, билатеральные и т.д.), тренировочные программы **T-Rex Arms**
   (их упражнения оформляются как курсы, не как базовые drills — см. §4.1;
   включая их NVG/full-kit контент), **тактические упражнения**: под ПНВ,
   с обязательной бронёй/шлемом, стресс-упражнения с физнагрузкой для стрельбы
   на пульсе; адаптации схем USPSA-классифайеров и Steel Challenge под карабин.
   Собственные тексты на русском, атрибуция происхождения. Ничего не
   выдумывается.
2. **Скрапер shootie.pro (MVP, dump-based):** библиотека этапов
   [shootie.pro/stages](https://shootie.pro/stages) — русскоязычное сообщество
   стрелков, контент за логином. Автоматический обход чужого логина запрещён;
   схема работы: пользователь (аккаунт у него есть) сохраняет страницы каталога
   локально (HTML/HAR), парсер `tools/scraper` конвертирует дампы в JSON схемы
   данных с `needsReview: true`; попадание в прод — после ручной вычитки
   (перевод не нужен — тексты уже RU; чистится форматирование, проставляются
   теги/атрибуция «shootie.pro» + автор, если указан).
3. **Фаза 2 — скрапер структурированных архивов:** библиотека
   USPSA-классифайеров (сотни курсов стрельбы) → JSON с `needsReview: true`
   → ручная вычитка + перевод.
3. CI-валидация данных на каждый push (§4).

## 10. Производительность

- First load JS < 50 КБ (gzip), Preact ≈ 4 КБ.
- Данные 100+ упражнений ≈ 200–300 КБ в сборке (gzip меньше).
- Precache всего приложения → полный офлайн после первого захода.
- Lighthouse: бюджет производительности держим, PWA-чек зелёный.

## 11. Точки расширения (спроектировано, не реализуется в MVP)

- `features/logbook` (фаза 2): запись подходов (время, очки, заметки),
  статистика по тегам, прогресс; хранение localStorage/IndexedDB;
  **экспорт/импорт JSON-файлом** — обмен с клубом без сервера.
- `features/calculators` (фаза 2): хитфактор (очки/время), конвертеры
  (м↔ярды, MOA↔MIL↔см на дистанции).
- `features/groupAnalyzer` (фаза 3): канвас, клики по мишени (потом фото) →
  extreme spread, СТП, размер группы, поправки — аналог Ballistic-X.
- `tools/scraper` (фаза 2) — см. §9.
- Дисциплины `shotgun`, `pistol-traumatic` — добавление контента без правок
  схемы.
- i18n EN-интерфейс; обёртка в Telegram Mini App (webview поверх того же PWA).

## 12. Риски и митигации

| Риск | Митигация |
|---|---|
| Доступность GitHub Pages из РФ нестабильна | Одна сборка → зеркало на Netlify/Vercel + опция свой домен |
| Объём ручной редактуры контента | Пайплайн: авторинг MVP по проверенным параметрам; скрапер с needsReview |
| Копирайт-претензии | Факты-параметры + собственные тексты + атрибуция + некоммерческий статус |
| SPA-роутинг на GitHub Pages | 404-fallback на index.html, hash-роутинг как запасной вариант |
| Разрастание медиа-кеша | Медиа только по требованию; кнопка «очистить кеш визуала» |
| Рост репозитория от своих медиафайлов (приоритет 2 в §7) | Бюджет ~≤2 МБ/файл; при росте — вынос в отдельную ветку/хранилище без смены архитектуры |

## 13. Тестирование

- **Vitest, юнит:** валидатор схемы данных (drills и courses); логика
  фильтрации/поиска; чистая функция layout→SVG (снапшоты); стейт-машина
  проигрывания `sequence`; логика таймера (пар-таймы, задержки).
- **CI:** валидация всех JSON → сборка → деплой. Невалидные данные ломают пайплайн.
- **Ручкой:** офлайн-режим (Airplane mode после первого захода), установка PWA
  на Android/iOS, таймер с бипом через Web Audio.
